Название продукта: WatchTimeTracker
1. Общие сведения
Краткое описание: Приложение для учёта времени, потраченного на задачи и проекты. CRUD проектов и задач и Таймер (старт/пауза /стоп) с записью в БД. Ручное добавление записей времени (если забыли включить таймер). Отчёт за период: суммарное время по каждому проекту/задаче. Фильтрация отчёта по датам.
Аудитория: Фрилансеры и разработчики, работающие со многими клиентами и проектами, студенты которые учитывают время на учебу, личные проекты, небольшие команды, которым например нужен простой трекер без корпоративных излишеств.
Формат пользования: веб приложение с локальным хранением данных.

2. Функциональные требования
MVP:
1. Пользователь может, создавать, редактировать и удаляет проекты.
2. Пользователь может, создавать, редактировать и удалять задачи. (внутри проекта)
3. Пользоваьтель может, запускать и останавливать таймер. (для выбранной задачи)
4. Пользователь может, добавлять запись о времени вручную. (начало, окончание, комментарий)
5. Пользователь может, просматривать список всех записей времени (фильтр по проекту)
6. Пользователь может, просматривать аналитику. (часы по проектам)
7. Пользователь может, редактировать и удалять записи времени.

3. Нефунциональные требования
Язык интерфейса: русский
Производительность: включение интерфейса – не более секунды  при операциях (открытие списка, старт/стоп таймера, построение отчета за день,неделю,месяц)
Хранение данных: локально в файле БД. Сеть не используется.
Защита от ошибок:
1. Нельзя сохранить проект или задачу без названия.
2. Нельзя указать дату окончание раньше даты начала.
3. Нельзя удалить проект, в котором есть задачи, без подтверждения.
4. Нельзя запустить еще один таймер, если идет уже один. (произойдет автостоп первого)
Инициализация БД: При первом запуске приложение создает таблицы из строенного SQL-скрипта.
Часовой пояс: время хранится по UTC, отображается в локальном часовом поясе.

6. Сценарии использования:
Сценарий 1: Учет времени через таймер
Актер: Пользователь 1
Предусловие: существует хотя бы один проект и одна задача в нем.
Основной поток:
1. Открывает  задачу и нажимает "Старт"
2. Система создает запись в текущее время и запускает отсчет на экране.
3. Работа над задачей.
4. Нажимает "Стоп"
5. Система заполняет и вычисляет время и сохраняет запись.
6. Система обновляет сводку по задаче и по проекту.
Альтернативный поток: если запускает второй таймер, то первый сделает автостоп.

Сценарий 2:  Ручное управление записи
Актер: Пользователь 2
Предусловие: уже существует проект и задача
Основной поток:
1. Пользователь открывает экран "Запись времени" и нажимает "Добавить"
2. Система показывает выбор формата: задача, время, комментарий.
3. Пользователь заполняет поля и нажимает "Сохранить"
4. Система проверит корректность.
5. Система сохранит запись и пересчитает время.
Альтернативный поток: если дата окончания раньше даты начала то система покажет ошибку и не сохраняет запись.

Сценарий 3: Удаление проекта
Актер: Пользователь 3
Предусловие: проект содержит задачи и записи времени.
Основной поток:
1. Пользователь жмет "Удалить" проект.
2. Система дает предупреждение "В проекте содержится "N" задач и "N" записей" Удалить все.
3. Пользователь нажимает на "Подтвердить"
4. Система удаляет задачи и связанные записи.
Альтернативный поток: Пользователь может передумать и не удалять проект.

7. Критерии приемки:
1. Приложение запустилось, и при старте создается БД со всеми таблицами.
2. Таймер запускается и останавливается без ошибок, и сохраняется запись со временем.
3. Можно добавить запись времени вручную, при неправильных датах должна выдаваться ошибка.
4. Список записей времени фильтруется по проекту, в задаче и дате.
5. Нельзя сохранить проект или задачу без названия.
6. Удаление проекта с задачами требует подтверждения.
7. Интерфейс первоначально должен быть на русском
8. Система должна обновлять сводку проекта сразу, по задаче и по записям.
