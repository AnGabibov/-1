# Проектирование слоя бизнес-логики (Service Layer)

## 1. Обзор слоя бизнес-логики
Слой бизнес-логики (Service) находится между контроллерами API и слоем доступа к данным (DAO). Его задачи:
- Валидация входных данных (проверка на пустоту, корректность дат).
- Соблюдение бизнес-правил (например, запрет на запуск второго таймера, защита от отрицательного времени).
- Координация нескольких вызовов DAO в рамках одной транзакции.
- Обработка исключений и возврат понятных сообщений об ошибках.

## 2. Бизнес-операции

### Операция 1: Управление таймером (Start/Stop Timer)
**Назначение:** Запуск или остановка отсчета времени для задачи (Сценарий 1 из брифа).
**Входные данные:** `projectName`, `taskName` (для старта) или `timeLogId` (для стопа).
**Результат:** ID новой записи (при старте) или объект с вычисленной длительностью (при стопе).
**Используемые SQL-запросы:** 
- `SELECT * FROM Projects WHERE Name = ?`
- `INSERT INTO TimeLogs (TaskId, StartedAt) VALUES (?, ?)`
- `SELECT * FROM TimeLogs WHERE Id = ?`
- `UPDATE TimeLogs SET EndedAt = ?, DurationSeconds = ? WHERE Id = ?`

**Алгоритм:**
1. Проверить, что входные данные (названия или ID) не пустые.
2. (При старте) Найти или создать проект и задачу.
3. Проверить, нет ли уже активного таймера (`EndedAt IS NULL`).
4. (При стопе) Найти запись, вычислить `DurationSeconds = (EndedAt - StartedAt).TotalSeconds`.
5. Если длительность < 0 — установить 0 (защита от сбоя часов).
6. Сохранить изменения в БД.

**Проверки:** 
- Названия не пустые.
- Таймер не запущен дважды.
- Длительность не отрицательная.

**Обработка ошибок:**
- Пустые данные → `ArgumentException` ("Название не может быть пустым").
- Таймер уже идет → `InvalidOperationException` ("Таймер уже запущен").
- Запись не найдена → `NotFoundException`.

**Тест-кейсы:**
1. *Успешный запуск и остановка:* Входные данные `projectName = "Учеба"`, `taskName = "Курсовая"`. Ожидаемое поведение: создается проект и задача, запускается таймер, через 10 секунд таймер останавливается. Ожидаемый результат: в БД запись с `StartedAt`, `EndedAt`, `DurationSeconds` ≈ 10.
2. *Запуск с пустым названием:* Входные данные `projectName = ""`, `taskName = "Курсовая"`. Ожидаемое поведение: система выдает ошибку валидации. Ожидаемый результат: `ArgumentException` ("Название проекта не может быть пустым"), запись в БД не создается.
3. *Остановка несуществующего таймера:* Входные данные `timeLogId = 9999`. Ожидаемое поведение: система ищет запись и не находит. Ожидаемый результат: `NotFoundException` ("Запись не найдена"), БД не изменяется.

### Операция 2: Ручное добавление записи времени (AddManualTimeLog)
**Назначение:** Добавление записи о времени без использования таймера (Сценарий 2 из брифа).
**Входные данные:** `taskId`, `startedAt`, `endedAt`, `comment`.
**Результат:** ID созданной записи.
**Используемые SQL-запросы:**
- `SELECT * FROM Tasks WHERE Id = ?`
- `INSERT INTO TimeLogs (TaskId, StartedAt, EndedAt, DurationSeconds, Comment) VALUES (?, ?, ?, ?, ?)`

**Алгоритм:**
1. Проверить, что `startedAt` меньше `endedAt`.
2. Проверить, что задача с таким `taskId` существует.
3. Вычислить `DurationSeconds`.
4. Сохранить запись в БД.

**Проверки:**
- `startedAt < endedAt`.
- Задача существует.
- `comment` не превышает 500 символов.

**Обработка ошибок:**
- Дата окончания раньше начала → `ArgumentException` ("Дата окончания не может быть раньше даты начала").
- Задача не найдена → `NotFoundException`.

**Тест-кейсы:**
1. *Успешное добавление:* Входные данные `taskId = 1`, `startedAt = 2026-11-17 10:00`, `endedAt = 2026-11-17 12:00`, `comment = "Работа"`. Ожидаемое поведение: проверки проходят, вычисляется длительность 2 часа. Ожидаемый результат: ID новой записи, в БД запись с `DurationSeconds = 7200`.
2. *Некорректные даты:* Входные данные `taskId = 1`, `startedAt = 2026-11-17 12:00`, `endedAt = 2026-11-17 10:00`. Ожидаемое поведение: система проверяет даты и видит, что окончание раньше начала. Ожидаемый результат: `ArgumentException` ("Дата окончания не может быть раньше даты начала"), запись в БД не создается.
3. *Несуществующая задача:* Входные данные `taskId = 999`, `startedAt = 2026-11-17 10:00`, `endedAt = 2026-11-17 12:00`. Ожидаемое поведение: система ищет задачу и не находит. Ожидаемый результат: `NotFoundException` ("Задача не найдена").

### Операция 3: Просмотр аналитики (GetAnalytics)
**Назначение:** Получение сводки по потраченному времени за период (Сценарий 3 из брифа).
**Входные данные:** `startDate`, `endDate`.
**Результат:** Список проектов с суммарными часами.
**Используемые SQL-запросы:**
```sql
SELECT p.Name, SUM(tl.DurationSeconds) / 3600.0
FROM TimeLogs tl
JOIN Tasks t ON t.Id = tl.TaskId
JOIN Projects p ON p.Id = t.ProjectId
WHERE tl.StartedAt >= ? AND tl.StartedAt < ? AND tl.EndedAt IS NOT NULL
GROUP BY p.Id, p.Name
ORDER BY 2 DESC;
