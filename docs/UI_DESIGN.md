# Проектирование пользовательского интерфейса (UI Design)

## 1. Полный список экранов приложения

На основе функциональных требований и сценариев использования из брифа, в приложении WatchTimeTracker выделены следующие экраны:

1. **Дашборд (Главная)** — активный таймер, сводка за сегодня, список проектов.
2. **Экран проекта** — список задач внутри выбранного проекта, суммарное время по проекту.
3. **Экран записей времени** — таблица всех записей с фильтрами и возможностью ручного добавления.
4. **Экран аналитики (Отчёт)** — суммарное время по проектам/задачам за период.

*(Экраны «Клиенты» и «Настройки» не входят в MVP, так как в брифе они не указаны в функциональных требованиях).*

## 2. Описание каждого экрана

### Экран 1. Дашборд (Главная)
- **Назначение:** Быстрый доступ к активному таймеру и обзор текущей активности.
- **Элементы управления:**
  - Кнопка «Старт/Пауза/Стоп» для активного таймера.
  - Список проектов (карточки с названием и временем за сегодня).
  - Кнопка «+ Проект» (переход к созданию).
  - Нижняя навигация (Главная, Записи, Аналитика).
- **Данные:** 
  - Имя проекта, время за сегодня (из таблицы `TimeLogs`).
  - Статус активного таймера (из `TimeLogs`).
- **Действия пользователя:** 
  - Нажать «Старт/Стоп» → система обновляет статус таймера в БД.
  - Нажать на проект → переход на экран проекта.
- **Реакция системы:** 
  - При старте: создается запись в `TimeLogs`, таймер начинает тикать.
  - При стопе: обновляется `EndedAt`, вычисляется длительность.
- **Обработка ошибок:** 
  - Если активный таймер уже запущен при попытке запустить новый — система автоматически останавливает первый (автостоп) и запускает новый (согласно п.4 «Защита от ошибок» брифа).

### Экран 2. Экран проекта
- **Назначение:** Управление задачами внутри проекта и запуск таймера на задачу.
- **Элементы управления:**
  - Кнопка «Назад» / хлебные крошки.
  - Заголовок проекта, суммарное время.
  - Список задач (каждая с кнопкой «▶» для старта/стопа и меню «⋯» для редактирования/удаления).
  - Кнопка «+ Задача».
- **Данные:** 
  - Список задач (из `Tasks`).
  - Время по задачам (из `TimeLogs`).
- **Действия пользователя:**
  - Нажать «▶» на задаче → запуск таймера.
  - Нажать «+ Задача» → открытие модального окна создания.
- **Реакция системы:** 
  - При запуске таймера — создается запись, кнопка меняется на «Стоп».
  - При создании задачи — добавление в список.
- **Обработка ошибок:** 
  - Пустое название задачи → сообщение «Название не может быть пустым» (п.1 «Защита от ошибок»).

### Экран 3. Записи времени
- **Назначение:** Просмотр, фильтрация и редактирование всех записей времени.
- **Элементы управления:**
  - Фильтры: выпадающий список «Проект», поле с датой (С, По), кнопка «Применить».
  - Таблица записей (дата, задача, длительность, комментарий).
  - Кнопки «Редактировать» и «Удалить» в каждой строке.
  - Кнопка «+ Добавить».
- **Данные:** 
  - Записи из `TimeLogs` с JOIN к `Tasks` и `Projects`.
- **Действия пользователя:**
  - Применить фильтр → обновление таблицы.
  - Нажать «+ Добавить» → открытие формы ручного ввода.
- **Реакция системы:** 
  - Обновление данных в таблице.
  - При удалении — каскадное удаление из БД.
- **Обработка ошибок:** 
  - Нет данных за период → сообщение «Нет записей».
  - Ошибка удаления → «Не удалось удалить запись».

### Экран 4. Аналитика (Отчёт)
- **Назначение:** Визуализация потраченного времени за период (день, неделя, месяц).
- **Элементы управления:**
  - Переключатель периода (День / Неделя / Месяц / Произвольный).
  - Поля дат (С, По).
  - Кнопка «Построить».
  - График (столбчатая диаграмма по дням).
  - Список проектов с прогресс-барами (доля времени).
- **Данные:** 
  - Агрегированные данные из `TimeLogs` (SUM по проектам и дням).
- **Действия пользователя:**
  - Нажать «Построить» → обновление графика.
- **Реакция системы:** 
  - Запрос к БД, построение графика.
- **Обработка ошибок:** 
  - Нет данных за период → «Нет данных для отображения».
  - Неверный диапазон дат → «Дата начала не может быть позже даты окончания» (п.2 «Защита от ошибок»).

## 3. Схема переходов между экранами

![Схема переходов](./diagrams/navigation.png)

*Основные переходы:*
- Дашборд → Проект (клик по карточке проекта).
- Дашборд → Записи (нижняя навигация).
- Дашборд → Аналитика (нижняя навигация).
- Проект → Задача (клик по задаче).
- Записи → Форма добавления (кнопка «+ Добавить»).

## 4. Пошаговые сценарии взаимодействия

### Сценарий 1: Учет времени через таймер (из брифа, Сценарий 1)
1. **Экран:** Проект.
2. **Действие:** Пользователь открывает задачу и нажимает «Старт».
3. **Система:** Создает запись в `TimeLogs` с текущим временем, запускает отсчет на экране.
4. **Действие:** Пользователь работает над задачей.
5. **Действие:** Пользователь нажимает «Стоп».
6. **Система:** Заполняет `EndedAt`, вычисляет `DurationSeconds`, сохраняет запись. Обновляет сводку по задаче и проекту.
7. **Альтернативный поток:** Если пользователь запускает второй таймер, первый автоматически останавливается (автостоп).

### Сценарий 2: Ручное добавление записи (из брифа, Сценарий 2)
1. **Экран:** Записи времени.
2. **Действие:** Пользователь нажимает «+ Добавить».
3. **Система:** Открывается модальное окно с полями: задача, время начала, время окончания, комментарий.
4. **Действие:** Пользователь заполняет поля и нажимает «Сохранить».
5. **Система:** Проверяет, что дата окончания не раньше даты начала. Если ошибка — сообщение «Дата окончания не может быть раньше даты начала» и запись не сохраняется.
6. **Результат:** Запись сохраняется в БД, время пересчитывается, таблица обновляется.

### Сценарий 3: Удаление проекта (из брифа, Сценарий 3)
1. **Экран:** Экран проекта (или Дашборд).
2. **Действие:** Пользователь нажимает «Удалить» у проекта.
3. **Система:** Показывает предупреждение: «В проекте содержится N задач и M записей. Удалить все?».
4. **Действие:** Пользователь нажимает «Подтвердить».
5. **Система:** Удаляет проект, все его задачи и связанные записи (каскадное удаление).
6. **Альтернативный поток:** Если пользователь нажимает «Оставить» — ничего не удаляется.
